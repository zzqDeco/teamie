# Official OpenAI Agentic model boundary

Gateway constructs the official CloudWeGo `github.com/cloudwego/eino-ext/components/model/agenticopenai.NewChatModel`. The configured API remains OpenAI-compatible **Chat Completions** at the administrator's HTTPS base URL plus `/chat/completions`. This does not require a Responses endpoint, server-hosted tools or a new owner setting. Identity, Chat and Realtime remain independent of Eino and provider configuration.

The implementation pins Eino `v0.10.0-alpha.35`, official `agenticopenai v0.2.3` and its ACL dependency `v0.1.18-0.20260923024851-c21d73d93527`. The later extension `v0.2.4` requires cache-write token fields absent from the pinned Eino alpha and fails compilation; upgrading Eino or patching the vendor model is outside this change. Compatibility is established by compiling the pinned sources and protocol fixtures, not by the extension's minimum version declaration alone.

Official references: [AgenticModel guide](https://www.cloudwego.io/docs/eino/core_modules/components/agentic_chat_model_guide/), [typed ChatModelAgent](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/agent_implementation/chat_model/), [extension v0.2.3 source](https://github.com/cloudwego/eino-ext/tree/components/model/agenticopenai/v0.2.3/components/model/agenticopenai) and [pinned Eino source](https://github.com/cloudwego/eino/tree/v0.10.0-alpha.35). Documentation was checked against those module sources because Context7 resolution returned its monthly quota error. Habitat's current Agentic implementation was used as a behavior reference; Teamie retains its own versions, contracts and provider policy.

## Native runtime and private transport

Runtime uses `NewTypedChatModelAgent[*schema.AgenticMessage]`, native Agentic Session/TurnLoop, and typed summarization/filesystem/background-task/PlanTask middleware. One Agent still has one global Session writer. The ADK runs function calls serially using the same durable tool receipts and explicit IM send tool. Reasoning and private assistant text never become IM messages automatically.

Runtime implements `model.AgenticModel` as a thin authenticated gateway client. Function manifests bind through the request's `model.WithTools` option; Agentic models have no mutable instance `WithTools` method. Forbidden, allowed, forced and named function choices remain request scoped. Generation temperature/top-p/stop and the bounded output limit are carried to the official adapter; gateway model selection always overrides any worker-supplied name. Deferred provider tool search and hosted MCP/server tools remain outside the preset platform tool policy.

`agent-protocol/modeltransport` defines a standard-library-only envelope: `{protocol:"teamie-agentic-chat-v1",messages,options,stream}`. Messages, response values and NDJSON chunks use Eino's `HumanReadableSerializer` so ordered blocks, streaming indices, token details and registered concrete metadata survive the process boundary and persistence. The runtime imports the extension only to register its metadata serialization/concatenation types; it does not instantiate a provider client or load provider credentials. The gateway alone owns OpenAI encoding, parsing and incremental block conversion. SQL tables remain owned by their respective services.

Unary generation uses `POST /internal/v1/chat`; streaming uses `POST /internal/v1/chat/stream` on the same private gateway HTTP service. Both require the runtime service Bearer credential, never a browser cookie or CSRF token. Caddy rejects `/internal/*` with 404. The runtime's gateway client routes generation over HTTP and keeps Kitex only for bounded Ping/Cancel operations. The old `ModelGatewayService.Chat` authenticates then immediately returns `protocol_unsupported`; it cannot start an unbounded provider request. A real generated Kitex-client/server regression demonstrated that canceling a plain Thrift call released the caller while its provider request and sole slot remained active. Hertz disconnect sensing provides the required remote cancellation, including before any response headers arrive, without relying on a best-effort Cancel RPC.

Provider transport policy wraps the official client: the existing public HTTPS endpoint validation, DNS resolution and public-address pinning, disabled proxies/redirects, body/token/tool limits, administrator model choice, single completion, serial tool preference, sanitized failure classes and incremental credential guard remain enforced. The guard checks raw/decoded stream fields before the official parser receives them, including split/Unicode-escaped credential fragments. Its response-body reader is synchronous and adds no upstream producer goroutine. Caller disconnect/cancel closes the upstream context; the runtime's close bridge also handles a consumer closing before any output arrives. Only a complete successful stream becomes a model receipt.

Inference has no default elapsed-time budget, including waiting for response headers. Unary HTTP, provider HTTP, the private streaming bridge and the gateway HTTP writer follow the caller's context, explicit close, revocation, lease loss and foreground preemption. DNS lookup, connection/TLS setup, IM/control operations, database initialization and detached usage-audit writes retain their operation-specific limits. The gateway overrides Hertz's write timeout to zero; Sandbox keeps its existing server defaults. At pinned Kitex `v0.16.4`, `WithRPCTimeout(0)` disables both the unary timer and [transport read deadline](https://github.com/cloudwego/kitex/blob/v0.16.4/pkg/remote/trans/common.go); it does not propagate cancellation to a plain Thrift handler, so generation cannot use that transport. The official Chat Completions adapter uses the injected HTTP client, and its pinned `go-openai v0.1.2` [request paths](https://github.com/meguminnnnnnnnn/go-openai/blob/v0.1.2/client.go) perform one HTTP call without a hidden retry or inference timeout. A caller may still supply its own deadline.

## Existing durable data and coordinated cutover

Stop the old runtime writer before replacing gateway/runtime images. Start the new gateway, then the new runtime; preserve the gateway database, encrypted key material, runtime database and Sandbox receipts/workspaces. There is no SQL schema migration in this format cutover. Gateway rejects unknown protocol versions before calling a provider. Mixing running old/new runtime and gateway binaries is unsupported and fails closed.

New writes use native Agentic messages. The Session store reads prior classic message, replacement, update, insertion and incomplete-stream events into native blocks without rewriting rows, event/message IDs, timestamps, extras, tool call IDs, source references or payload hashes. Existing summaries retain their provenance index. An opaque classic checkpoint is never decoded as an Agentic checkpoint: its version is rejected, and the same durable run/input starts again using its pinned history and receipts.

Read compatibility recomputes the former byte-exact request hash before accepting a classic model receipt; any changed source/options/tool manifest fails with `replay_conflict`. Legacy streamed tool indices and sender names are retained solely for this check. New native receipt fingerprints exclude only Eino's regenerated `_eino_msg_id`; actual transport/Session records preserve it, and source IDs plus all other audit data remain hashed. No native receipt can use the legacy fallback. Tool call, stable send, Sandbox request and background task identities do not include the runtime format version. Crash-window tests cover a committed IM send, native task acceptance and PlanTask effects across this cutover.

The v0.3.6 recovery patch derives a private per-Run tool profile from committed receipts. A Run containing classic receipts keeps the v0.3.4 IM tool manifest and legacy summary provenance formatting for its whole lifetime, even after appending native receipts and restarting. A fresh Run uses the current manifest, including `im_get_attachment`, and the v0.3.5 summary format. Checkpoint compatibility includes the profile; an incompatible checkpoint falls back to the same durable Run and its receipts. This is an internal replay property, not an additional runtime layer or owner configuration.

IM tools emit their durable observation bytes directly for both first execution and replay. For older outputs that were reserialized by the ADK, compatibility uses only the same Run's actual recorded tool-result messages and matching completed tool receipts. It must preserve summary token accounting and reproduce a stored full request hash; only the tool-result text may vary. Native receipts still cannot use the classic message codec. Changed policy, source messages, tool arguments, tool manifests or unrelated outputs remain conflicts. Receipt hashes and already committed IM sends are never rewritten. Terminal failed Runs require an explicit existing internal retry; deployment does not bulk-requeue them.

## Verification boundary

Local TLS/HTTP fixtures exercise the actual official adapter's generation and incremental streaming, reasoning/text/function ordering, function identity, common options, tool choices, detailed usage/metadata, credential suppression, provider errors and cancellation. Disposable PostgreSQL tests exercise lossless native persistence, classic event/receipt reads, incompatible checkpoint rejection, stable replay of IM/task/file effects, authorization and lease fencing. These are protocol and durability checks. Real-provider/model behavior remains unverified until an administrator configures and authorizes that acceptance.

Lifetime regressions include real local TLS responses whose headers arrive after 51 seconds, a private HTTP response after 16 seconds, virtual-clock unary inference lasting 90 seconds and active streams lasting nine minutes with a complete durable receipt. Silent header/body cancellation, explicit stream close and abandoned-reader collection must all terminate promptly without a partial receipt. The two real header-delay regressions are skipped only with `go test -short`.
