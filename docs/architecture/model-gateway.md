# Official OpenAI Agentic model boundary

Gateway constructs the official CloudWeGo `github.com/cloudwego/eino-ext/libs/acl/openai.NewAgenticClient`. Its public response modifiers preserve typed metadata and normalize streaming block identities before SDK output callbacks and private transport serialization. The configured API is OpenAI-compatible **Chat Completions** at the administrator's HTTPS base URL plus `/chat/completions`. Identity, Chat and Realtime remain independent of Eino and provider configuration.

The implementation pins Eino `v0.10.0-alpha.35`, official `agenticopenai v0.2.3` and its ACL dependency `v0.1.18-0.20260923024851-c21d73d93527`. The later extension `v0.2.4` requires cache-write token fields absent from the pinned Eino alpha and fails compilation; upgrading Eino or patching the vendor model is outside this change. Compatibility is established by compiling the pinned sources and protocol fixtures, not by the extension's minimum version declaration alone.

Official references: [AgenticModel guide](https://www.cloudwego.io/docs/eino/core_modules/components/agentic_chat_model_guide/), [typed ChatModelAgent](https://www.cloudwego.io/docs/eino/core_modules/eino_adk/agent_implementation/chat_model/), [extension v0.2.3 source](https://github.com/cloudwego/eino-ext/tree/components/model/agenticopenai/v0.2.3/components/model/agenticopenai), [pinned AgenticClient source](https://github.com/cloudwego/eino-ext/blob/c21d73d93527/libs/acl/openai/agentic_client.go) and [pinned Eino source](https://github.com/cloudwego/eino/tree/v0.10.0-alpha.35). Context7 documentation and the pinned sources establish the modifier ordering and native concatenation contract. Habitat's Agentic implementation was used as a behavior reference; Teamie retains its own versions, contracts and provider policy.

## Streaming identity adapter

The pinned ACL converter can reuse a content-block index for text and a tool call when content arrives between fragments of tool arguments. Native concatenation then rejects the mixed block types. It can also split interleaved fragments of the same tool into separate blocks. The related upstream report is [eino-ext #975](https://github.com/cloudwego/eino-ext/issues/975).

Each gateway request owns a small adapter through the official `WithResponseChunkMessageModifier` and `WithResponseChunkAgenticMessageModifier` hooks. Before conversion, it captures only the original tool-call indices, content-part identities and response metadata. After conversion, it assigns one stable block index to every original tool index and separate indices to contiguous content segments. A tool keeps its identity across intervening reasoning, text and other tools. Payload conversion remains in the official client. The adapter clones block headers before changing indices and never inserts temporary markers into native `Extra`, callbacks or receipts. A final metadata-only chunk and EOF without such a chunk are both supported.

The direct client is necessary because the pinned `agenticopenai.ChatModel` wrapper appends its own modifiers after caller options, replacing those hooks. Gateway composes the equivalent unary/streaming metadata behavior using the public `agenticopenai.ChatResponseMetaExtension`; response ID, finish reason, log probabilities and native token usage retain their registered serialization and concatenation types. The adapter uses the existing dependency versions without a fork, vendored patch or `replace` directive. Native wire versions, historical receipt bytes/hashes and runtime replay rules are unchanged.

## Native runtime and private transport

Runtime uses `NewTypedChatModelAgent[*schema.AgenticMessage]`, native Agentic Session/TurnLoop, and typed summarization/filesystem/background-task/PlanTask middleware. One Agent still has one global Session writer. The ADK runs function calls serially using the same durable tool receipts and explicit IM send tool. Reasoning and private assistant text never become IM messages automatically.

Runtime implements `model.AgenticModel` as a thin authenticated gateway client. Function manifests bind through the request's `model.WithTools` option; Agentic models have no mutable instance `WithTools` method. Forbidden, allowed, forced and named function choices remain request scoped. Generation temperature/top-p/stop and the bounded output limit are carried to the official adapter; gateway model selection always overrides any worker-supplied name. Deferred provider tool search and hosted MCP/server tools remain outside the preset platform tool policy.

`agent-protocol/modeltransport` defines a standard-library-only envelope: `{protocol:"teamie-agentic-chat-v1",messages,options,stream}`. Messages, response values and NDJSON chunks use Eino's `HumanReadableSerializer` so ordered blocks, streaming indices, token details and registered concrete metadata survive the process boundary and persistence. The runtime imports the extension only to register its metadata serialization/concatenation types; it does not instantiate a provider client or load provider credentials. The gateway alone owns OpenAI encoding, parsing and incremental block conversion. SQL tables remain owned by their respective services.

Unary generation uses `POST /internal/v1/chat`; streaming uses `POST /internal/v1/chat/stream` on the same private gateway HTTP service. Both require the runtime service Bearer credential, never a browser cookie or CSRF token. Caddy rejects `/internal/*` with 404. The runtime's gateway client routes generation over HTTP and keeps Kitex only for bounded Ping/Cancel operations. Foreground model calls across different Agents run concurrently under a bounded gateway slot pool (`DefaultMaxConcurrentCalls = 16`, configurable via `GATEWAY_MAX_CONCURRENT_CALLS >= 2`); excess concurrent calls receive retryable `429 gateway_busy` before invoking the upstream provider. The old `ModelGatewayService.Chat` authenticates then immediately returns `protocol_unsupported`; it cannot start an unbounded provider request. A real generated Kitex-client/server regression demonstrated that canceling a plain Thrift call released the caller while its provider request and sole slot remained active. Hertz disconnect sensing provides the required remote cancellation, including before any response headers arrive, without relying on a best-effort Cancel RPC.

Provider transport policy wraps the official client: the existing public HTTPS endpoint validation, DNS resolution and public-address pinning, disabled proxies/redirects, body/token/tool limits, administrator model choice, single completion, serial tool preference, sanitized failure classes and incremental credential guard remain enforced. The guard checks raw/decoded stream fields before the official parser receives them, including split/Unicode-escaped credential fragments. Its response-body reader is synchronous and adds no upstream producer goroutine. Caller disconnect/cancel closes the upstream context; the runtime's close bridge also handles a consumer closing before any output arrives. Only a complete successful stream becomes a model receipt.

Inference has no default elapsed-time budget, including waiting for response headers. Unary HTTP, provider HTTP, the private streaming bridge and the gateway HTTP writer follow the caller's context, explicit close, revocation, lease loss and foreground preemption. DNS lookup, connection/TLS setup, IM/control operations, database initialization and detached usage-audit writes retain their operation-specific limits. The gateway overrides Hertz's write timeout to zero; Sandbox keeps its existing server defaults. At pinned Kitex `v0.16.4`, `WithRPCTimeout(0)` disables both the unary timer and [transport read deadline](https://github.com/cloudwego/kitex/blob/v0.16.4/pkg/remote/trans/common.go); it does not propagate cancellation to a plain Thrift handler, so generation cannot use that transport. The official Chat Completions adapter uses the injected HTTP client, and its pinned `go-openai v0.1.2` [request paths](https://github.com/meguminnnnnnnnn/go-openai/blob/v0.1.2/client.go) perform one HTTP call without a hidden retry or inference timeout. A caller may still supply its own deadline.

## Existing durable data and coordinated cutover

Stop the old runtime writer before replacing gateway/runtime images. Start the new gateway, then the new runtime; preserve the gateway database, encrypted key material, runtime database and Sandbox receipts/workspaces. There is no SQL schema migration in this format cutover. Gateway rejects unknown protocol versions before calling a provider. Mixing running old/new runtime and gateway binaries is unsupported and fails closed.

New writes use native Agentic messages. The Session store reads prior classic message, replacement, update, insertion and incomplete-stream events into native blocks without rewriting rows, event/message IDs, timestamps, extras, tool call IDs, source references or payload hashes. Existing summaries retain their provenance index. An opaque classic checkpoint is never decoded as an Agentic checkpoint: its version is rejected, and the same durable run/input starts again using its pinned history and receipts.

Read compatibility recomputes the former byte-exact request hash before accepting a classic model receipt; any changed source/options/tool manifest fails with `replay_conflict`. Legacy streamed tool indices and sender names are retained solely for this check. New native receipt fingerprints exclude only Eino's regenerated `_eino_msg_id`; actual transport/Session records preserve it, and source IDs plus all other audit data remain hashed. No native receipt can use the legacy fallback. Tool call, stable send, Sandbox request and background task identities do not include the runtime format version. Crash-window tests cover a committed IM send, native task acceptance and PlanTask effects across this cutover.

The v0.3.6 recovery patch derives a private per-Run tool profile from committed receipts. A Run containing classic receipts keeps the v0.3.4 IM tool manifest and legacy summary provenance formatting for its whole lifetime, even after appending native receipts and restarting. A fresh Run uses the current manifest, including `im_get_attachment`, and the v0.3.5 summary format. Checkpoint compatibility includes the profile; an incompatible checkpoint falls back to the same durable Run and its receipts. This is an internal replay property, not an additional runtime layer or owner configuration.

IM tools emit their durable observation bytes directly for both first execution and replay. For older outputs that were reserialized by the ADK, compatibility uses only the same Run's actual recorded tool-result messages and matching completed tool receipts. It must preserve summary token accounting and reproduce a stored full request hash; only the tool-result text may vary. Native receipts still cannot use the classic message codec. Changed policy, source messages, tool arguments, tool manifests or unrelated outputs remain conflicts. Receipt hashes and already committed IM sends are never rewritten. Terminal failed Runs require an explicit existing internal retry; deployment does not bulk-requeue them.

The v0.3.7 summary recovery handles a provider response whose `finish_reason` is `length` and which contains reasoning but no visible text or tool calls/results. Eino's native typed summarization failover makes one additional generation with the same model, input and options. Each generation remains a separate durable model step: retrying an older failed Run replays its invalid receipt and appends the replacement instead of rewriting historical responses or hashes. A second empty response or a tool-bearing summary still fails without replacing the Session or emitting an IM message. Previously accepted nonempty `length` summaries retain their behavior so later committed steps replay exactly.

Qwen3.8 Max enables thinking by default. For that model family and its named snapshots, the gateway sends top-level `enable_thinking:false` only when the request forbids tools and has no tool manifest, which is the current summary shape. The official client's `openai.Config.ExtraFields` carries the option, and the provider boundary validates its boolean type. The runtime envelope, persisted request fingerprint and existing output limits do not change; ordinary tool-enabled turns keep their reasoning policy. This follows [Alibaba's thinking-mode documentation](https://www.alibabacloud.com/help/en/model-studio/deep-thinking) and the pinned Eino [summarization implementation](https://github.com/cloudwego/eino/blob/v0.10.0-alpha.35/adk/middlewares/summarization/summarization.go), whose optional failover-model selector defaults to reusing the original model and input. No inference-duration limit is added.

## Verification boundary

Local TLS/HTTP fixtures exercise the actual official adapter's generation and incremental streaming, reasoning/text/function ordering, function identity, common options, tool choices, detailed usage/metadata, credential suppression, provider errors and cancellation. Disposable PostgreSQL tests exercise lossless native persistence, classic event/receipt reads, incompatible checkpoint rejection, stable replay of IM/task/file effects, authorization and lease fencing. These are protocol and durability checks. Real-provider/model behavior remains unverified until an administrator configures and authorizes that acceptance.

Streaming regressions use synthetic payloads with the observed production chunk shapes (288 reasoning + 224 tool fragments, and 10 reasoning + 143 tool fragments). They check nonempty text inside one call, empty text, content before tools, interleaved calls, concurrent requests and a stream ending directly on content. Native serialization and concatenation must retain exact tool arguments/call IDs, complete JSON, all reasoning/text and typed response metadata.

Summary regressions persist five model and two tool receipts, including the reasoning-only failure, then restart the same Run twice: recovery appends step six with the same request hash, the next restart reuses it, and the already committed send remains singular. Separate cases reject another empty response, an empty normal completion and tool-bearing replacements. The real official-adapter TLS fixture verifies the top-level Qwen option while other models and ordinary turns remain unchanged.

Lifetime regressions include real local TLS responses whose headers arrive after 51 seconds, a private HTTP response after 16 seconds, virtual-clock unary inference lasting 90 seconds and active streams lasting nine minutes with a complete durable receipt. Silent header/body cancellation, explicit stream close and abandoned-reader collection must all terminate promptly without a partial receipt. The two real header-delay regressions are skipped only with `go test -short`.

## Long-context transport

Snapshot version 6 removes the historical 4K output clamp for newly admitted Runs. With a 1000000-token declared window, Runtime initially requests 32768 and reserves up to 131072 output tokens; both the official adapter configuration and provider request normalization honor that ceiling, also bounded by one quarter of the configured window. Historical Runs still send their exact original options. Native requests allow 16 MiB and 65536 messages; the gateway overrides Hertz's request-body ceiling for the double-encoded private envelope. Native responses, provider SSE, private NDJSON and single-frame limits are aligned with large outputs. Admin browser input, IM files and Sandbox limits are unchanged.

Frozen output admission belongs to the logical Runtime Run. The gateway honors that request up to the 131072-token protocol ceiling; it does not clamp an existing Run to a later administrator window. The declared window changes admission for new Runs only.

## Independent administrator configuration

`Config` is an aggregate read snapshot of `Providers` (`ProviderProfile`), `Models` (`ModelProfile`), `ModelRoutingConfig` and `WebSearchConfig`; it is not a persistence command. Provider updates manage endpoint URL, encrypted API key and provider enablement; model updates bind a catalog `id` to a `providerId`, upstream `model`, declared `contextWindowTokens` and model enablement; routing updates change only default selection; and search updates change only search state and credentials. Multiple `ModelProfile` entries may share one `ProviderProfile` without duplicating `baseUrl` or `apiKey`. Runtime resolves a read-only `ResolvedModel` combining `ModelProfile` and its parent `ProviderProfile` for each inference call; it never copies fallback model fields back into administrator settings. Strict per-model tests (`WithStrictRequestedModelID`) resolve only the requested model ID without fallback so disabled or unconfigured profiles fail explicitly with `409`. Provider inference receives only that resolved model, without search secrets or the full catalog.

The retired combined PUT returns `config_api_changed` without writes. Read-only legacy metadata remains available for existing acceptance tooling. The web administrator groups models under provider cards with separate provider dialogs, model dialogs, per-model test result state (`Record<modelId, outcome>`), default selection actions and a search form, each with its own submission state. Secret inputs start empty; successful search or provider saves never echo saved credentials.

In-flight calls track their resolved model profile ID. Disabling/deleting a model profile, or disabling its parent provider / clearing that provider's credential, cancels all in-flight calls whose resolved model has become unavailable while search calls and healthy providers/models continue uninterrupted. Catalog mutations (`UpdateCatalog`) exclude the short configuration-lookup-to-cancellation-registration phase so provider or model revocation cannot miss an admitting call. The admission lock is released before provider execution and does not serialize inference. Cancellation registration retains both the admitted model ID and provider ID: moving a model does not reassign an already running call, so revoking the old provider cancels only its calls and revoking the destination provider does not cancel old-provider calls. Administrator connection tests also retain a request generation; successful catalog/routing writes invalidate affected results and late responses cannot verify the new configuration or clear a newer test's busy state.

Schema 6 introduces `gateway_providers` alongside schema 5's `gateway_models`, `gateway_model_routing` and `gateway_web_search_config`, and enforces a `ValidateGatewaySchema` startup fence (`<= 6`). Existing schema-5 `gateway_models` rows backfill 1-to-1 into `gateway_providers` (copying `base_url` and `encrypted_key` verbatim without re-encryption or merging by `base_url`) before enforcing `gateway_models.provider_id NOT NULL REFERENCES gateway_providers(id) ON DELETE RESTRICT` and dropping the redundant columns from `gateway_models`. Non-empty providers return `409 provider_in_use` on deletion. `PGStore.Load` reads routing, web search, providers and `(created_at, id)`-sorted models in a single PostgreSQL MVCC query snapshot. Release manifests declare Gateway 6; cross-schema rollback follows the existing backup/restore policy.
