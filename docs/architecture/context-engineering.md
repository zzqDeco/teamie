# Private Agent context engineering

Teamie keeps one global Session per Agent and one serial native TurnLoop writer. Context reduction, summaries, archive reads and background completion inputs are Runtime internals. IM has no Eino dependency, and browsers cannot inspect this private context.

## Versioned execution policy

Runtime schema 3 adds immutable `context_profile` and `context_budget` to each logical Run. Existing rows use `teamie-context-v037` and retain the original tools, prompts, summaries and model-receipt hashes. Explicit `agents.context.v1=true` admits new Runs with `teamie-context-v038`; disabling admission does not change an already admitted Run or erase durable data. A saved budget includes the declared model window, input/output reserves, transport ceiling, counter version, reduction thresholds and recent-tail bound. Recovery loads that snapshot rather than recomputing from current gateway settings. Native checkpoints bind both profile and budget hash.

New Runs use budget snapshot version 2. It reserves one quarter of the declared window, capped at 8192 output tokens, while initially requesting at most 2048. Summary output retains its 2048-token ceiling. The input limit accounts for the full reserve before dispatch. If a complete provider response exhausts output without a tool call, or contains syntactically incomplete function arguments, Eino's native model verdict can retry with the reserved capacity before any tools run. The rejected response remains a model receipt; replay repeats the verdict from that receipt and keeps committed effects unchanged. Continued truncation at the frozen reserve fails as `upstream_response_limit` instead of completing the turn. Mid-stream errors/cancellation retain their existing classification. Version 1 budgets retain their exact capacity, prompts, request hashes and retry behavior; no old row is rewritten. This changes per-response capacity without adding an execution lifetime limit or another runtime layer.

Current admission uses budget snapshot version 4. Complete current Run inputs are matched to their trusted source envelopes and kept outside historical summarization and tail offload, including batches from several conversations. Historical messages/tool rounds shrink first. A soft reduction target cannot override this requirement; if the policy/tools and current body cannot fit the hard capacity, execution fails before another model call. Private task checkpoints may consume a notification by resuming their suspended tool; any visible notification envelope is preserved as well. Historical source closure remains in message metadata and immutable archive references instead of repeating large source-ID arrays in provider-visible notices. Version 3 reserves at most 4096 output tokens, matching the Gateway's existing maximum. Versions 1, 2 and 3 retain their original transformations and capacities.

Version 4 coalesces individually small historical observations and archive pointers before offloading recent results. Complete current inputs remain pinned, the two newest complete units are retained whenever the hard capacity allows, and older observations stay in immutable source-scoped archives. This prevents repeated file reads from losing their results while small historical fragments fill the window. Committed empty/error context-retrieval observations retain their actual request-source provenance even when no data parent exists. Forged observations remain rejected, and later reads recheck those source ACLs. Archive failures stop before model dispatch; no context is silently discarded.

This is a policy version inside the existing runtime, not another execution service. Eino remains `v0.10.0-alpha.35` with the official `agenticopenai v0.2.3` gateway adapter. Habitat's newer local `origin/dev` was inspected at `34ed3daf1f430b238d4f5cc33fb91166b15deb42`; it uses Eino `v0.9.13` and adapter `v0.2.2`. Its native reduction, source-aware prefix compaction and transcript retrieval informed the work. Its per-conversation orchestration and tool catalog are not adopted into Teamie's continuous Session.

## Model input pipeline

The new pipeline reduces large tool observations before summarization. It retains the platform policy, summarizes an older prefix, and keeps a bounded exact suffix of complete recent request/assistant/tool groups. Call and result pairs are not split. Original source requests remain represented even after long tool sequences. Capacity checks account for serialized messages, tools, summary input/output and the independent gateway byte ceiling; shrinking message count alone cannot prove a request fits.

Large observations and compacted transcript projections receive immutable private archive references. `context_read` retrieves UTF-8 byte pages; `context_search` finds relevant observations in the fixed Session view. These tools revalidate the Agent, worker lease and current ordinary IM access to their real source references, including on cached reads. Actual IM tool receipts bind the returned conversations, messages and attachments, independently of the conversation that triggered the Run. Provenance fragments keep large source sets complete across repeated history reads. Replayed reads retain their original observation rather than discovering artifacts from later Runs. Retrieval pages are not recursively offloaded, and a summary of them inherits the original server-recorded source references. Reasoning blocks, signatures, provider metadata and service/provider credential fields are excluded from transcript projection. This does not redact secrets a participant puts into ordinary message text. The archive lives in Runtime's database and is not mounted into Sandbox execution children.

Provider context failures use a small sanitized error allowlist. General authentication, rate-limit and malformed-request errors do not trigger compaction. DashScope's documented input-range error is recognized only with its corresponding structured invalid-parameter code ([official error reference](https://www.alibabacloud.com/help/en/model-studio/error-code)). A pre-output context rejection is durably recorded with its request hash, mode, policy and decision before native recovery. A successful receipt and a context rejection cannot occupy the same model step. Partial streaming failures remain distinct and cannot be silently converted into a successful retried response. Native retry observations do not themselves fail a Run that subsequently succeeds.

## Progressive workspace and task observations

New-policy Runs advertise private `workspace_read_page` for file, directory, glob, grep and task-output pages. Responses state coverage, continuation and version so a model can distinguish a preview from a complete result. UTF-8 byte pages can traverse long single lines and files larger than the legacy 256 KiB text-read ceiling. Mutations keep their existing bounds and isolated workspace paths.

Workspace observations use a conservative source closure for the Agent's shared workspace. Only its durable writer, authenticated attachment-import and actual task intents contribute; a writer also inherits the earlier Session/history/summary sources in its fixed causal view. A later conversation that did not write the workspace does not change an earlier writer or read snapshot. Sources are frozen before effects or cached results are returned, and current IM access is checked again on replay. Task output binds the actual stored task ID and originating Run. Small original results, offloads, transcript projections and derived summaries retain this closure. Paths, copied source markers and file contents cannot grant source access.

This is not a per-file origin ledger. Shell commands can rename, link or rewrite files, so a new read or write can conservatively depend on other files' recorded writer sources. Removing a source can therefore deny otherwise unrelated workspace operations. Deleting or rebuilding files does not establish a trusted workspace generation and does not clear these origins; an automatic generation reset is not implemented. An unknown legacy import without an authenticated source proof fails closed. Older synchronous `workspace_execute` writer receipts are included; a legacy writer with an unprovable earlier Session view also fails closed. A previously fixed page checks only its original frozen sources, even if another writer arrives later.

New archive and index provenance carries an internal version in the existing private observation journal. Older workspace offloads are revalidated against their exact original tool identity, arguments, result and committed receipt, including on cached reads. Summary parent links come from persisted application events and verified archive references, never claims in summary text. An old derived summary without enough provenance remains unavailable when its fixed view included workspace observations. Original native history with sufficient source evidence remains available through source-checked indexing. This validation does not rewrite historical tool/model receipts or request hashes. If a UTF-8 byte budget cannot fit the next complete rune, paging returns an explicit invalid request instead of a successful nonadvancing continuation.

Command output is captured in trusted Sandbox state independently of the small model preview. Durable output has explicit physical storage limits and completeness metadata; crossing the preview length does not terminate a new-policy command. Legacy tasks retain their receipt format and replay semantics. An unproven gap in recovered daemon logs is incomplete evidence, never fabricated complete output or permission to rerun an unknown effect.

Background tasks retain their parent Run and actual source reference set in private snapshots. Completion inputs recover that origin from Runtime's own task/Run rows. They do not guess an audience from the newest active conversation. Multiple sources and incomplete bounded reference sets remain explicit; all IM sends still require an explicit destination and current IM authorization.

## Verification and rollout

Meaningful verification covers native reduction and prefix/tail behavior; real PostgreSQL archive visibility, write-once identity, source ACL revocation and restart replay; model-recovery tape ordering; long file and output pages; task origin; and legacy Run compatibility. Provider protocol fixtures establish these mechanics, not real-model decision quality. No new browser diagnostic UI or deployment environment is introduced.

The current release schema vector is Identity 3, Chat 5, Control 1, Runtime 6, Gateway 2. Runtime migrations 4, 5 and 6 mark budget-version-2, version-3 and version-4 reader support and raise the existing writer protocol fence. They preserve all earlier rows and receipts, and prevent an older image from starting against a newer durable format. Stop the old Runtime writer before migration and dependency replacement, verify the pre-upgrade backup, and deploy immutable ACR digests. Cross-schema image rollback is rejected. Preserve all previous release branches/tags and saved administrator gateway configuration.
