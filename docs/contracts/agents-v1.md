# Agent API and execution contract — v0.3.3

This contract extends the independent IM product. IM services do not depend on Eino, model configuration, runtime sessions, or sandbox state. New services use separate Go modules, PostgreSQL databases/roles, container images and authenticated Kitex contracts in `contracts/agent.thrift`.

## Product decisions

- A human creates and owns each Agent. Agent ID equals its independent IM participant ID. Ownership does not confer access to other participants' conversations.
- Owner settings are name, description, selected workspace IDs, and enabled state. No user-supplied model, provider, key, prompt, tool, or budget controls in this release.
- Agent working context is private across its authorized conversations. A human owner manages the basic profile, workspace visibility and enabled state only. Ownership and platform administration do not grant browser access to Session, run, task, tool, error or activity details.
- Selected teams are workspace-level visibility. Only workspaces where the owner is currently a member may be selected. Agents use ordinary workspace/conversation membership and IM ACLs. Removing the granting owner revokes delegated memberships. Moderator removals must not be undone by background reconciliation.
- One durable Session per Agent (`agent:<id>`) intentionally carries working memory across its authorized conversations. Session compaction preserves provenance and original message references. IM history is never deleted by compaction.
- Newly committed message bodies, sender identity, workspace/conversation/message/event IDs and an optional parent `replyToId` enter the runtime inbox promptly. Self-authored messages are not new work. Each Agent has one Session writer and one serial native TurnLoop. Worker/Attempt/lease/fence are private implementation details; they do not add architecture services or owner settings. Fresh input delivery is independent of the current run batch.
- Distant history is read through explicit IM tools. Every chat write is an explicit tool invocation with an explicit destination. Ordinary model output and operational errors are never automatically published to IM.
- Platform administrators configure the shared OpenAI-compatible model gateway. A healthy but unconfigured gateway produces `model_unconfigured`; Agents wait without losing their inbox. Releases preserve the administrator's saved gateway configuration and credentials.
- Tools and Sandbox are platform presets. Execution children have no provider/IM credentials, host Docker socket, network, or arbitrary host mounts. Workspace lifetime and execution-container lifetime are independent.

## Owner and discovery HTTP

All endpoints require a human cookie session. Writes require the existing CSRF and trusted Origin checks. Agent bearer credentials cannot manage definitions. Platform admin is not an ownership bypass.

Public `Agent` JSON has exactly `{id,principalId,ownerId,ownerName,name,description,workspaceIds,enabled,createdAt,updatedAt}`. `principalId=id`. A separate public DTO projects these fields for every create, update, read, list and discovery response. No runtime state, Session ID, activity timestamp, error, revision, tombstone or other internal metadata is returned. `enabled` is the owner's saved configuration; it does not assert online status or model/provider health. Internal configuration revisions still fence runtime changes; there is no public revision/If-Match contract.

- `GET /api/v1/agents` -> `{agents:[Agent]}` owned by caller.
- `POST /api/v1/agents` body `{name,description?,workspaceIds,enabled?}` -> 201 `{agent}`. Empty workspace IDs are allowed; the Agent has no team membership until a team is selected.
- `GET /api/v1/agents/:id` -> `{agent}` owner only.
- `PATCH /api/v1/agents/:id` accepts optional `name`, `description`, `workspaceIds`, `enabled` -> `{agent}` owner only. Profile/visibility changes fence old configuration revisions. Disable revokes IM credentials and stops active work.
- `DELETE /api/v1/agents/:id` -> 204 owner only. Tombstone definition, revoke credentials/membership and cancel work; preserve attributable IM message history. Deleted profiles return 404 on public reads and are excluded from listings/discovery.
- `GET /api/v1/workspaces/:id/agents` -> `{agents:[Agent]}` discovery only for current members, selected visibility and actual Agent membership. Each profile's `workspaceIds` contains only the requested workspace ID, including when the caller is the owner. Other selected workspaces remain private. The owned profile endpoints retain the owner's full selected list.

Public capabilities: `agents.enabled`, `agents.create`, `agents.update`, `agents.delete`, `agents.discover`. Existing `im.dm.create` and `im.group.create` govern conversations. Disabled write features preserve persisted profiles/history. Personal Agent profile management uses `/app/agents` and `/app/agents/:id`, reached from the Agent button immediately above the account avatar at the bottom of the leftmost workspace rail. The avatar menu contains account settings and sign out. The workspace member directory at `/app/w/:workspaceId/members` lists humans and visible Agents together with an Agent badge and uses the ordinary IM conversation/member APIs. The sidebar has no standalone member-directory entry; conversation headers still open the current conversation member list and its invitation action. The workspace title is plain text; its adjacent plus opens capability-gated direct and group creation. Workspace switching and creation use the workspace rail. `/app/w/:workspaceId/agents` redirects to this directory. Turning discovery off preserves persisted Agent members and conversations, but does not admit new Agent selections. The account settings page exposes platform management only to human platform administrators; administrator pages are absent from the main navigation.

## Administrator model gateway HTTP

Gateway owns encrypted provider secrets and configuration in its own database. Only `platformRole=admin` human sessions may access these APIs. Private key bytes must never appear in reads, logs, frontend caches, URLs, or Sandbox requests.

- `GET /api/v1/admin/model-gateway` -> `{config:{baseUrl,model,hasApiKey,enabled,configured,contextWindowTokens,updatedAt},status:"unconfigured"|"ready"|"disabled"}`. `ready` describes saved configuration, not observed upstream health.
- `PUT /api/v1/admin/model-gateway` body `{baseUrl,model,apiKey?,enabled,clearApiKey?,contextWindowTokens?}` -> same redacted response. Omitted `apiKey` preserves the stored key. `clearApiKey` explicitly removes it and cannot accompany a new key.
- `POST /api/v1/admin/model-gateway/test` -> `{ok,model,latencyMs}`. Test saved configuration using one small real model request; the UI labels this effect. CI uses a disposable protocol fixture; production uses only administrator-supplied credentials.

`contextWindowTokens` defaults to 16384, accepts 4096–2000000 and is preserved when omitted. It is an administrator declaration for bounded runtime summarization, not a capability probe. Frontend route `/app/admin/gateway`; existing invitation admin route is preserved. Service readiness is independent of whether a model is configured.

All versions expose private `/healthz`, `/readyz`, `/version`. Only Caddy publishes host ports. The deployment stays a single production environment.

- `AgentControlService.ListAgents/GetAgent/ReportRuntime` use `AGENT_RUNTIME_TOKEN` and shared generated Agent definitions. List includes disabled/deleted definitions so workers cancel stale work. Runtime reports contain only safe operational state.
- Private model generation uses `POST /internal/v1/chat` (unary) and `POST /internal/v1/chat/stream` (NDJSON), authenticated only by `Authorization: Bearer <GATEWAY_RUNTIME_TOKEN>`. Browser sessions and CSRF tokens do not authorize these endpoints, and the public edge returns 404 for `/internal/*`. Both modes attribute calls to owner, Agent, Session and run. Their private `requestJson` is a versioned `teamie-agentic-chat-v1` envelope containing serialized native Eino `AgenticMessage` input, common request-level model options and the stream mode. `responseJson` and NDJSON chunks contain native `AgenticMessage` values using Eino's lossless serializer, including ordered reasoning/text/function blocks and concrete response metadata. The gateway alone uses the official `agenticopenai.NewChatModel` extension to produce OpenAI Chat Completions requests. Gateway owns model selection; worker-supplied model names cannot bypass the configured policy. HTTP disconnect/cancellation ends the provider call without a fixed inference budget. `ModelGatewayService.Chat` is retired and returns `protocol_unsupported` after authentication without starting a provider call: ordinary Thrift unary cancellation does not cancel its remote handler. Bounded Kitex `Ping`/`Cancel` remain operational. Unknown protocol versions fail closed. Runtime and gateway must be upgraded together with the runtime writer stopped; see [model gateway architecture](../architecture/model-gateway.md).
- `SandboxService.Start/Get/ReadOutput/CancelTask` uses `SANDBOX_RUNTIME_TOKEN`; accepts Agent/task IDs, command and optional execution deadline. Persist intent, bounded output, cancellation and result outside the workspace. Known async containers are adopted after supervisor restart; unknown effects are not rerun. `Get` returns `ok=false/errorCode=task_not_found` for an absent receipt; a durably accepted queued task is `ok=true/state=not_started` and remains recoverable. File RPC is confined to the Agent workspace and mutation IDs recover write/edit/delete receipts. Legacy bounded `Exec` remains compatible. Image, mounts, network and resources are platform configuration.
- IM generic principal provisioning uses `IM_PRINCIPAL_CONTROL_TOKEN`. Runtime-only principal token issuance/validation uses `IM_PRINCIPAL_RUNTIME_TOKEN`. Tokens expire and are revoked on disable/delete. Ordinary IM HTTP requests use `Authorization: Bearer <principal-token>` and `X-Teamie-Service-Key`; no human browser can impersonate an Agent. Tools use current IM APIs and ACLs, not another service's database.

## Runtime durability and tools

The runtime owns inbox cursor, pending inputs, worker leases/fencing, run state, Eino Session events, checkpoints, compaction state and tool receipts. IM sync is the durable input source; WS/Redis only accelerate wakeups. Persist events before advancing the source cursor, deduplicate source events, revalidate membership when processing delayed inputs, and keep recovery isolated from configuration revisions.

Preset tools: list authorized conversations, query/paginate IM history, fetch a referenced message or sequence context, explicitly send/reply, native filesystem/PlanTask tools, recoverable workspace execution, and native task progress/control tools. Each result is a runtime observation, not an automatic chat post. Send intent and stable `clientMessageId` survive retries; output is acknowledged only after IM persistence. Tool-call recovery must not duplicate already committed sends or unknown external side effects. Gateway calls and cancellation use a distinct execution-attempt ID. Sandbox preserves durable run/request IDs for receipt replay and carries a separate optional executionId for cancellation, so stopping one attempt cannot poison its later retry.

### Explicit IM file import

Fresh inputs and explicit history/message reads include only `attachments:[{id,filename,mediaType,sizeBytes,sha256}]` descriptors. File-only messages are durable new inputs. No binary, base64, automatic URL fetch, file parsing or IM send occurs during inbox ingestion or prompt construction. Structured message/source IDs continue to identify the original audience. A file name and its contents remain untrusted data.

`im_get_attachment({conversationId,messageId,attachmentId,path})` explicitly downloads a known file from a known source message into the calling Agent's Sandbox. It first reads that message under the Agent's current ordinary IM identity, confirms the descriptor, then downloads through Chat's authenticated content endpoint under the same current ACL. Foreign/unlinked/retracted/removed-access files remain unavailable. No arbitrary external URL or host path is accepted. A real byte-length/SHA-256 check precedes import. The tool returns a path, byte count and hash; file content never appears in the JSON tool observation. Native text reads remain limited to 256 KiB UTF-8; binary processing is an explicit Sandbox execution step.

Internal `SandboxService.ImportFile(SandboxImportRequest)` carries a Thrift `binary` field, Agent/run/stable request ID, confined path and SHA-256. It uses the runtime service credential only in the supervisor RPC; execution children receive no IM/service/provider credentials or network. The runtime rechecks configuration authorization and the worker lease immediately before import. A retry reuses the logical run/tool-call identity, independent of execution attempt. Sandbox stores a private intent before atomic no-replace publication and a completion receipt afterwards. It reconciles a lost result only when the exact expected bytes exist; ambiguous intervening changes return `execution_unknown`. Receipt replay preserves later file edits and never overwrites another existing file. Agent workspaces and trusted receipts are physically separate; traversal, target/parent symlinks and outside-root paths are rejected.

The shared IM file limit is 4 MiB, fitting under the existing execution child's 8 MiB `fsize` limit. Import/text mutation admission also accounts for the Agent workspace's 64 MiB/4096-entry budget; supervisor monitoring cancels execution that crosses the observed budget. This is admission plus sampled monitoring, not a kernel hard aggregate filesystem quota. Existing child memory/CPU/PID/output/network restrictions remain enforced. Sandbox RPC bounds framed payload size to the file ceiling plus a small metadata allowance. Chat schema advances to 3; Runtime/Gateway/Control/Identity schema versions do not change for files. Existing PostgreSQL backup/restore includes IM files; durable Sandbox files/receipts remain in the existing protected Sandbox roots.

Native summarization stores a bounded source-aware summary plus recent coherent message/tool-call groups. Its model request explicitly forbids tool calls (`tool_choice=none`) and asks for plain summary text; empty or tool-bearing summaries remain invalid and cannot execute IM tools. Ordinary Agent turns retain their tool access. Summary requests fit the configured context window and transport limit. Long-term Session persistence and interrupted execution checkpoints are separate. Compatible native checkpoints use Resume; recovery retains model/tool receipts and the run's pinned Session view. A model configuration error leaves durable inputs available for retry after configuration.

Native Eino background TaskStore, TaskEventStore, NotificationOutbox and writer protocols are implemented in PostgreSQL. A stable logical task ID survives replay. Manager/executor activity and Sandbox execution do not write the Session in parallel; durable completion notifications return through its input queue. The foreground model slot is released during task waits. Async shell has no default command lifetime limit; request transport deadlines do not determine command lifetime. Ordinary gateway streams preserve upstream content/tool deltas and usage, with distinct explicit HTTP, in-stream, interruption and cancellation outcomes.

While the serial TurnLoop handles validated new IM inputs, Runtime publishes the ordinary IM typing signal for those input conversations through the generic Realtime HTTP API. It starts only after acquiring the host's foreground slot; the initial slot queue, idle Session, distant history and background-only task notifications do not advertise activity. The signal remains active during tools within that turn and refreshes every 1.5 seconds after rechecking the current Agent configuration, cancellation and fenced worker lease; each HTTP publication also rechecks ordinary IM ACLs. No global Session-busy broadcast is inferred for other conversations.

Turn completion, error, preemption, cancellation, lease loss or configuration invalidation stops the refresh and attempts `isTyping=false`. Refreshes and final clears are serialized and joined before another turn's signal starts. Transport failures never fail the turn; refresh/cleanup requests are bounded to one second, and a crash, disabled flag or revoked credential falls back to the existing five-second browser TTL. `IM_REALTIME_URL` defaults to private `http://realtime:8083`; no host port or new deployment environment is added. Browser hints contain only the normal public participant name/ID and conversation typing boolean. Public Agent profiles retain their exact ten-field contract; no Session, run, task, tool, error or activity endpoint is exposed.

Agent execution uses `NewTypedChatModelAgent[*schema.AgenticMessage]`, a native Agentic Session/TurnLoop and typed summarization/filesystem/task middleware. Tool manifests bind per request through `model.WithTools`; `WithAgenticToolChoice` preserves forbidden, automatic, required and named function choices. Summaries explicitly forbid tool calls. Existing classic Session events remain readable without changing their event IDs, message IDs, source references or stored hashes. Incompatible classic opaque checkpoints are not resumed: the same durable run/input replays verified model/tool/task receipts. A classic model receipt is accepted only when the byte-exact former request hash matches; altered inputs fail with `replay_conflict`. No SQL schema change or receipt/IM send identity change accompanies this format cutover.

## Behavior guidance

Platform-owned [behavior guidance](../product/agent-behavior.md) governs direct/group participation, explicit destination selection, source-scoped privacy, untrusted message/tool/file content, concise product-facing replies, truthful task progress and receipt-aware recovery. Summarization preserves source attribution and does not promote quoted requests into platform instructions. No owner prompt setting or browser instruction/runtime endpoint is added. Prompt compliance and cross-conversation information flow are model behavior, not a new server authorization guarantee; real-provider behavior remains a separate acceptance gate.

## Private runtime boundary

There are no browser runtime inspection or control APIs. The former routes below return 404 for every caller, including the human owner and platform administrators. They do not authenticate/proxy runtime requests or call internal Runtime RPC:

- `GET /api/v1/agents/:id/runtime`.
- `GET /api/v1/agents/:id/runs` and `GET .../runs/:runId`.
- `GET /api/v1/agents/:id/tasks` and `GET .../tasks/:taskId`.
- `GET /api/v1/agents/:id/events` and `GET .../events/stream`, including JSON and SSE requests and reconnect headers.
- `POST /api/v1/agents/:id/runs/:runId/cancel`, `POST .../runs/:runId/retry`, and `POST .../tasks/:taskId/cancel`.

Agent Control has no outgoing runtime client or `AGENT_RUNTIME_RPC_ADDR` dependency. Internal runtime RPC, its authentication, Session/TurnLoop, durable tasks/events/checkpoints, cancellation/retry and operational diagnostics remain private service functionality. No new administrator debugging UI is part of this contract. IM history and explicit Agent messages remain accessible through ordinary current conversation ACLs.

Default flags revision `agents-v2` adds `agents.runtime.v3` (new runtime work) and `agents.tasks.execute` (new task submission). This is one runtime implementation with feature admission controls, not a permanent second engine. Disabling submission preserves internal task observation/cancellation and persisted public profiles/IM history; it does not enable browser runtime routes.

## Release acceptance

Required public acceptance: exact profile-field allowlist, owner isolation, workspace-scoped discovery without other team IDs, membership revocation, 404 for all retired runtime routes with no runtime RPC access, non-impersonation, redacted admin gateway settings, unchanged invitation/IM flows and desktop/mobile interaction. Private runtime Go integration tests separately cover the continuous Session, arrival of fresh input during an active turn, native checkpoint resumption, source-aware summarization, send deduplication, lease exclusion, native task-store conformance, durable completion wakeup, known Sandbox recovery, cancellation/retry and incremental streaming with partial-failure classification. Public acceptance must not infer these private execution properties from profile metadata. Real provider acceptance remains pending until administrator configuration and authorization; protocol fixtures must be identified as verification infrastructure.

Release `v0.3.3` from exact checked `main` using a new permanent `release/v0.3.3` archive. This prompt-changing cutover requires the quiescent-writer precondition in [behavior guidance](../product/agent-behavior.md); same-version receipt tests do not establish compatibility of old unpinned cached retries with new request text. Preserve all previous release branches/tags, including the failed `release/v0.3.1` archive. Existing accounts/workspaces/messages and gateway settings remain persisted; the schema vector is unchanged at Identity 2, Chat 2, Control 1, Runtime 2, Gateway 2. Stop the old runtime writer before dependency replacement/migration; quiesce legacy synchronous Sandbox work before its first async upgrade. New ACR image digests, runtime flag identity and execution runner image belong in the release manifest. Cross-schema image rollback is rejected; take and verify a pre-upgrade backup.
