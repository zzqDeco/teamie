# Gateway and Sandbox

Independent Go module: `teamie/agent-infra`. The shared Thrift/Kitex module is `../agent-protocol`; only generated Identity RPC types/client are imported from `../backend`. No IM service imports this module. Read `../docs/contracts/agents-v1.md` for the public contract and `../ops/README.md` for production upgrade/recovery.

`cmd/llm-gateway` exposes private HTTP8086/RPC8886. Required environment: own `DATABASE_URL`, `APP_ORIGIN`, `GATEWAY_MASTER_KEY` (64 hex characters), `GATEWAY_RUNTIME_TOKEN` (at least24 characters). `IDENTITY_RPC_ADDR` defaults to identity:8881. `cmd/sandbox` exposes private HTTP8087/RPC8887 and requires `SANDBOX_RUNTIME_TOKEN`, `SANDBOX_RUNNER_IMAGE`, protected/disjoint `SANDBOX_WORKSPACE_ROOT` and `SANDBOX_STATE_ROOT`; Docker socket defaults to /var/run/docker.sock. All services expose /healthz,/readyz,/version; version/SHA are injected at image build. Production Compose uses only immutable GHCR runner digests; the local CI launcher may use an immutable local sha256 image ID.

Gateway administrator HTTP is cookie/Identity-RPC authenticated, human-admin-only and CSRF/Origin protected for writes. Provider credentials are AES-256-GCM encrypted in Gateway's own PostgreSQL database, omitted keys preserve the saved key, explicit clear deletes it, and reads expose only `hasApiKey`. No provider key is needed for readiness. Saved config status is `unconfigured`, `disabled` or `ready`; `ready` means saved configuration is complete and enabled, not a successful live provider test. The explicit test endpoint sends one small real request using only saved, enabled configuration.

Runtime Chat RPC requires its scoped service token, attribution IDs and non-streaming OpenAI chat-completion JSON. Gateway overwrites model/n/stream, bounds messages/tools/payload/token count, allows one call and at most50 seconds, records owner/agent/session/run usage counters, and returns safe error codes without raw provider errors. No model output is automatically published to IM. Only public HTTPS provider endpoints are accepted; every DNS address is checked again and pinned on dialing, redirects and environment proxies are disabled, and success bodies containing the provider credential are rejected. Logs/usage never contain prompt, completion or credential bodies. Usage retains at most roughly100,000 rows/30 days through bounded hourly pruning. Explicit Cancel remembers recent cancellation for two minutes, so a cancel arriving just before dispatch still prevents a provider request. Gateway run IDs include the durable run and a fresh execution-attempt ID; a later attempt remains eligible.

Sandbox accepts command and bounded identifiers/timeout only. Fixed image, one per-Agent hash workspace bind mount, UID10001, no network/secrets/socket, read-only root, cap-dropALL/no-new-privileges, 0.5CPU/128MiB/no swap/32PIDs/128FDs/8MiB file limit/16MiB tmp/64KiB combined output are supervisor policy. Commands use a non-login shell, default to30 seconds, max60. Output attaches before process start; exceeding64KiB terminates the child and preserves the bounded prefix with truncated=true. Nonzero child exit codes are successful execution observations (`ok=true`, nonzero `exitCode`); infrastructure/cancellation/unknown outcomes have `ok=false` and a structured `errorCode`. A 2GiB disk reserve is checked before and every100ms during jobs; a10,000-receipt bound rejects new identities instead of expiring records and rerunning side effects.

A protected receipt intent is fsynced before Docker create. The final result is saved only after the ephemeral container has been removed. Same request ID and fingerprint returns the existing result; changed run/command/timeout conflicts. Interrupted intent or failed cleanup stays `execution_unknown`; inspect side effects before a deliberately new request. Startup removes only managed-label containers after acquiring an exclusive supervisor lock. Workspace state survives container deletion; receipts are never exposed to jobs. Database dumps do not contain Sandbox workspaces/receipts: back up both roots together while the runtime/execution is quiesced. Provider decryption also requires a separate protected backup of GATEWAY_MASTER_KEY.

Run `go test -race ./...`, `go vet ./...`, `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build ./...`. `DATABASE_URL_TEST` enables unique-schema PostgreSQL encryption/persistence/usage tests. `SANDBOX_TEST_RUNNER_IMAGE` enables real Docker filesystem/network/secrets/resource/output/timeout/cleanup verification on disposable CI; it is explicitly skipped when unset. Protocol-accurate TLS provider fixtures exist only in tests through injected clients, with no production SSRF bypass or real external API calls. `ops/ci-agent-acceptance.sh` launches a fresh disposable full stack and drops only its unique databases on exit; local diagnostics may explicitly skip Sandbox and print that limitation.
